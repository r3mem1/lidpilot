# Проверка сайта глазами пользователя

Смоук-тесты проверяют API; этот скилл — то, что видит человек: тексты, кнопки,
скрипты страниц, время и пояса, ответы бота клиенту. Код при проверке не правится —
итог: список находок и предложений, правки — после согласования с пользователем.

## 1. Стенд (никогда не прод)
```bash
python scripts/qa_stand.py up            # в фоне (run_in_background): сброс qa_site.db, демо-данные, сайт :8770
python scripts/qa_stand.py up --keep     # перезапуск без сброса
python scripts/qa_stand.py say 1001 "какие окна на завтра?" --name Олег   # написать боту как клиент
python scripts/qa_stand.py inbox 1001    # что получил клиент
```
Стенд изолирован: своя БД и секреты, AI_PROVIDER=stub, Sentry выключен, поддельный Telegram
(:8771) пишет «отправленное» в `.qa/telegram.json`. Аккаунты: demo@ / manager@ / admin@example.com,
пароль Demo-Pass-123. Токен бота в кабинете — любой вида `123:ABC…`.
Windows: перед командами `export PYTHONUTF8=1`.

## 2. Сценарии (MCP playwright, Яндекс.Браузер)
Идти как новый пользователь, а не через демо-компанию:
1. Вход: неверный пароль → понятная ошибка; регистрация (короткий пароль, нормальный).
2. Создание компании → чек-лист «Обзор» по шагам: услуги (цена «1 500»), мастера и их услуги,
   смены, пояс и «Запись к мастерам» в настройках, подключение бота.
3. Клиенты (`say`): окна на завтра / вечером / «а в пятницу?», запись неполной фразой
   («на стрижку», «на бороду», ответ номером), цены, адрес, график, скидки, «опоздаю»,
   перенос/отмена, жалоба, бессмыслица. Читать ответы глазами клиента: понятно ли, нет ли цикла.
4. Кабинет: диалог (причина, ручной ответ → клиенту), «Записи» (подтвердить/отменить → что
   получил клиент), «Проверка ответа», лиды, клиенты, аналитика.
5. Роли: пригласить менеджера и мастера по ссылке, войти ими, проверить меню и «Уведомления».
6. `/admin` под admin@. Мобильный экран 390×844 (скриншот в `.qa/`).

## 3. Что искать
- Служебные коды и англицизмы в интерфейсе (`[A-Z_]{5,}`, `None`, `NaN`, «0 мс»): обойти страницы
  `fetch` + DOMParser. Время без `<time>` выводится в UTC — сверять с живой страницей.
- Расхождение текста страницы и поведения (обещано сообщение клиенту — проверить `inbox`).
- Шаблон со своими `data-*` хуками без `<script src="/static/js/pages.js">` — форма молча
  отправится GET-ом.
- Консоль браузера (`browser_console_messages`): ожидаемые 4xx отличать от поломок.
