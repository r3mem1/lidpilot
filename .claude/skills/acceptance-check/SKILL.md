# Приёмка по ТЗ §21

Для каждого пункта: найти существующий автоматический тест или написать его; запустить; в отчёт — только реально полученный результат. Пункт, который этап ещё не покрывает, → «⏳ не в scope этапа N», а не «✅».

| № | Критерий (§21) | Как проверить | Этап |
|---|---|---|---|
| 1 | После регистрации владелец создаёт компанию и добавляет услуги | `smoke_test.py`: register → POST /businesses → POST services | 1 |
| 2 | Компания может подключить Telegram-бота | тест интеграции: сохранение токена/secret, `setWebhook` (mock), секрет не возвращается API | 3 |
| 3 | Сообщение попадает в backend через webhook | POST /webhooks/telegram с верным secret → 200 | 3 |
| 4 | Сообщение сохраняется в БД | запись в messages с `external_message_id` | 3–4 |
| 5 | AI определяет intent и priority | `smoke_test_ai.py`, значения сохранены в message/lead с reason | 2, 4 |
| 6 | AI использует данные конкретной компании | две компании с разными ценами → ответы различаются | 2 |
| 7 | AI не придумывает отсутствующие цены/условия | услуга без цены/несуществующая → нет выдуманных значений | 2 |
| 8 | Ответ отправляется клиенту | mock Telegram sendMessage вызван 1 раз, message(AI) сохранён | 3 |
| 9 | Диалог отображается в кабинете | GET /businesses/{id}/conversations + страница messages.html (Playwright) | 5 |
| 10 | Менеджер может вручную ответить | POST /conversations/{id}/reply от MANAGER → отправлено и сохранено | 4–5 |
| 11 | Горячий лид виден в отдельном списке | GET /businesses/{id}/leads?priority=HOT + страница leads.html | 4–5 |
| 12 | ADMIN видит компанию в панели | GET /admin/businesses под ADMIN, `/admin` страница | 6 |
| 13 | ADMIN видит ошибки и события системы | GET /admin/logs содержит события AI/Telegram/UNHANDLED_ERROR | 6 |
| 14 | Пользователь одной компании не получает данные другой | скилл `tenant-isolation-check` + тесты 404 на все ресурсы | 1+ |
| 15 | После временной ошибки внешнего API сообщение не теряется | LLM/Telegram падают → сообщение в БД, событие в логе, возможность повтора | 3–4 |

## Порядок
1. Определи текущий этап по `CLAUDE.md`/коду; отметь пункты вне scope.
2. Запусти: `python smoke_test.py && python smoke_test_ai.py` и тесты новых этапов.
3. UI-пункты (9, 11, 12) — через Playwright MCP: логин → страница → скриншот → консоль без ошибок.
4. Убедись, что логи (§17) позволяют по одному `message_id` восстановить: получено → классифицировано → почему такой ответ → отправлено/эскалировано.
5. Выведи итоговую таблицу: `№ | статус (✅ / ❌ / ⏳) | доказательство (тест/команда/скриншот)` и общий вердикт: «этап N принят / не принят». Для ❌ — что именно не работает и где.
